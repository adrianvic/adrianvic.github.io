Prologue

I've been using OPL to stream games from my home server since I returned to the PS2. However, this solution didn't prove to be very convenient, since it required me to host an insecure SMB1 server, and the loader UI isn't the best.

I then decided to search for something better, and found OSD-XMB, an open-source project aiming to give PS2 players the look and feel of Sony's XMB design language, shipped with some of their consoles (PS3, PSP) and media players. Personally, I think it's gorgeous; although I've only experienced XMB in a media player as a kid, I would say that the devs managed to capture the snappyness of the thing, which I didn't think was possible on the PS2 without a crazy level of coding.

And that's to the credit of OPL, OSD-XMB uses some tricks to maintain itself alive without crazy amounts of work; it's written in JavaScript, more specifically on top of AthenaEnv—a JS environment for the PS2. For instance, OSD-XMB takes much more time to load in comparison to OPL, and in the end these little things are up to you to decide which one is worth. Ah, and I didn't mention that OSD-XMB does not support Samba... So that's how we got here.

The problem

I have a PS2 slim with a faulty disk drive, meaning that I cannot play disks nor attach a hard drive to my console, so I rely on my home server, let's say... serving (ba doom tss) ISO files to the console.

Furthermore, I rely on a single SSD for my server operations, so making a new partition just to serve UDPDB would be a pain in the ass. That would mean I have to not only reserve a fixed amount of storage for my games—and delete games when it fills up; I would also lose maximum storage in my data partition. That's why I'll be using a specific UDPDB server that can serve a folder instead of a partition.

OSD-XMB vaguely mentions to support UDPDB in their README, with instructions pointing to an issue. However while following these instructions I could not get it to, in order:

  1. Find my server
  2. Not crash when loading the "Playstation 2"
  3. Boot games

The solution

First, we have to find a suitable server. I'll go with PS2-Servers, but you can use anything that works for you. The binary from the release page did't have support for serving a folder. However, since the thing is written in Python I just cloned it's repo and ran:

# clone and enter the repo
git clone https://github.com/NathanNeurotic/PS2-Servers
cd PS2-Servers

# make a venv to hold dependencies and install them
pyhton -m venv .venv
source .venv/bin/activate
pip -r requirements.txt

# run the server
# replace /srv/ps2 with your games folder in the usual DVD/, CD/ format
python ps2servers.py serve udpbd --virtual-exfat /srv/ps2

The next step is to enable smap_udpdb in athena.ini (set it to true) as that will load the required Neutrino module; the module intentionally lies about network being unavailable to OSD-XMB network stack, or else they would conflict—so you will lose OSD-XMB online features.

Then you should "edit APPS\neutrino\config\bsd-udpbd.toml with the appropriate IP address for your environment", which is where the tutorial kinda falls apart. Is this meant to be the PS2 or server address? Turns out it's the PS2 address, but only for launching games. You shouldn't need to change this, as you'll see next, you'll have to adapt your server to PS2's hardcoded IP address anyway.

When booting the console will always use 192.168.1.10 as it's address. My network uses a /24 subnet mask, meaning my server that has an address in the 192.168.18.XX format could not access the PS2's 192.168.1.XX. To fix that I just had to tell the server it should have an address in the other subnet, without erasing the current one:

# get your active interface name
ip route show default

# give yourself the address 192.168.1.50, which is in the PS2 subnet
sudo ip addr add 192.168.1.50/24 dev <interface_name> # replace with your interface

Then the "Playstation 2" folder showed on Games menu. However upon opening it would freeze the UI. I have no experience on OSD-XMB codebase, but I found the solution to this by removing features of the game list until it worked. Ended up with this patch to PLG/gme_999_xPS2.xml:

Near line 86, replacing the init block with this one:

<Init>
  <![CDATA[
    function SetPS2Icons(SubMenu) {
      delete SubMenu.Init;
    }
  ]]>
</Init>

And that's it. I can now launch PS2 games from my server with the gorgeous XMB interface, and hope you can too.
